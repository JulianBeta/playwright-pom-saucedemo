# BUG-016: Deep links answer HTTP 404

|                    |                                                                          |
| ------------------ | ------------------------------------------------------------------------ |
| **Severity**       | Low                                                                      |
| **Type**           | Infrastructure / Observability                                           |
| **Affected users** | all users                                                                |
| **Environment**    | https://www.saucedemo.com · Chromium, Firefox, WebKit · found 2026-11-02 |
| **Status**         | Worked around in framework                                               |

## Steps to reproduce

1. Request `https://www.saucedemo.com/cart.html` (or any page other than `/`) directly, e.g. with curl.

## Expected

HTTP 200 with the page.

## Actual

HTTP 404 with a script that redirects to `/?/cart.html` (GitHub Pages single-page-app workaround). Users don't see it, but monitoring, link checkers and crawlers report every deep link as broken.

## Automated test

Handled by `src/utils/navigation.ts` (`openDeepLink` waits for the real app after the redirect)
